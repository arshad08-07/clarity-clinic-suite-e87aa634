# Clarity Clinic Suite

Build a complete production-grade Eye Clinic / Eye Hospital Management System using React + TypeScript with a proper relational backend/database. Do not create a frontend-only mockup. All modules must use real persistent database data.

The application must manage the complete clinic lifecycle from lead and patient registration through appointment, check-in, queue, optometry, eye examination, doctor consultation, diagnosis, prescription, diagnostics, surgery, OT, IOL/implant management, pharmacy, optical shop, contact lenses, inventory, procurement, billing, payments, expenses, insurance, CRM, communication, follow-ups, patient portal, reports, staff, doctors, equipment, branches, roles, permissions, notifications, audit logs and settings.

Build the application as a scalable multi-role system with Super Admin, Clinic Admin, Receptionist, Doctor, Optometrist, Nurse, Pharmacist, Optical Staff, Inventory Manager, Accountant, Diagnostic Staff and CRM/Marketing Staff roles.

Implement proper authentication, authorization, role-based permissions, database relationships, validation, error handling, loading states, empty states, search, filtering, pagination, date ranges, exports, printing and responsive design.

The system must support both medical and commercial workflows. Medical records, prescriptions, diagnostic reports, surgery records, financial records and inventory must be linked to the patient wherever applicable.

The architecture must support multiple clinic branches even if the first deployment uses only one branch.

Do not skip eye-clinic-specific functionality such as visual acuity, refraction, OD/OS measurements, IOP, eye examination, diagnoses, OCT, visual field, biometry, cataract workflow, surgery scheduling, OT management, IOL/implant tracking, post-operative follow-up and optical prescription management.

Build reusable components and avoid duplicated code. Create a clean professional medical dashboard, responsive on desktop, tablet and mobile.

Before implementation, create the complete information architecture, database schema, role/permission matrix and screen/module structure. Then implement the system phase by phase without changing the underlying architecture unnecessarily.

The final result must be a working clinic management product, not a UI prototype.
